# 就业罗盘 · 演示讲解词（按评审六部分）

> 对着运行中的程序讲，全程约 8–10 分钟。括号内是手上操作，其余照读。
> 录制前：服务已启动（`./start.sh --dify`），浏览器开 `http://127.0.0.1:3000`。

## 1. 问题与需求（约 1 分钟）

（操作：停在工作台首页）

这个项目面向**中国校招、社招求职者**，以及参加算法竞赛、黑客松的开发者。

我们调研中发现的痛点可以归纳为「三个不信任」：

- 第一，**AI 会编造经历**——模型替用户"写"简历，把团队成果写成个人成果，投出去就是诚信风险；
- 第二，**攻略来源不明**——网上和 AI 给的求职攻略像聊天回答，时间、出处无法核对，用过期规则准备当届比赛很常见；
- 第三，**建议空泛**——"提升综合素质"这类话无法执行、无法验收。

需求来源很直接：求职者要的不是一份"看起来漂亮"的简历，而是**能核对、能执行、能交付**的准备材料。

## 2. 项目目标（约 40 秒）

（操作：指向首页五步流程导航）

就业罗盘要解决的核心问题一句话：**让 AI 参与求职准备，但每一步都可核对**。

关键功能对应首页这五步：上传简历 → 核对信息 → 比较岗位 → 修改简历 → 练习面试，最后导出可投递的报告。

我们给自己定了一条硬原则：**不能确认就不生成**——信息不足就追问，没有联网凭据就明确标注"未联网核验"，绝不伪装成功。

## 3. 技术方案（约 2 分钟）

（操作：切到终端或架构说明，不用切走也可以口头讲）

技术上是四层架构：

- **前端** Next.js 16 + React 19，步骤式工作台；
- **业务层** FastAPI，负责任务编排、引用校验，以及我们的核心亮点——**确定性规则引擎**；
- **工作流层** 本地 Dify 1.19，17 个已发布工作流，提示词版本化管理；
- **模型与检索层**：千问负责写作和出题、DeepSeek 负责评审复核、Tavily 负责联网检索，所有凭据只保存在服务端。

重点讲一下**规则引擎**（操作：切到浏览器演示）。

（操作：首页滚到「先用示例看看结果」，点「载入示例」）

我现在载入一份虚构示例——它的匹配和反馈**完全由规则引擎生成，不调用模型**，正好可以展示这套机制。

（操作：等结果出来，指向六维评分区域）

岗位适配分由六个维度加权：技能 25%、经历相关 25%、学历 15%、科研 15%、奖项竞赛 10%、求职意向 10%。每个维度都是明确规则：

- 技能看必需/优先技能命中率，**每缺一项必需技能总分折减 15 分，下限 25**；
- 经历不只看有没有，还交叉验证"负责、主导、交付"等质量词；
- 科研、奖项只识别简历原文，国家级/省级/校级分层计档——**没有就不得分，绝不编造**。

知识库方面，本地维护了 55 条带来源的中国职业条目；工具调用上，网页内容一律视为不可信数据，私网地址和重定向直接拦截。

## 4. 创新与价值（约 1 分半）

（操作：点开一个岗位的详细得分和诊断报告）

和现有方法比，我们的改进体现在三点：

**第一，确定性评分先于模型生成。** 同一份简历永远算出同一个分数，每个数字能指回具体规则、随时可复算。纯模型打分做不到这一点。

**第二，事实锁定。** 每条 AI 生成的句子都映射到用户已确认的事实 ID；画像一改，旧草稿自动标记失效。诊断报告给出的「亮点前置、普通简化」建议完全由六维得分驱动——科研和国奖得分高，就建议放到简历前三分之一；没有科研经历，就建议不单设栏目，不写空话。

**第三，引用可核对、诚实降级。** 「已查证」结论必须带来源 ID 和逐字片段，由后端校验——模型说了不算。断网或查无资料时明确标注，通用建议和官方要求分开呈现。

体验价值上：用户拿到的不是一段聊天文字，而是带来源、带评分拆解、可直接打印成 PDF 的交付文档。

## 5. 当前成果（约 2 分钟）

（操作：实机演示，依次操作）

已经实现的功能我直接演示：

（操作：指向画像核对区）

简历上传后先核对画像——技能、教育、项目、意向城市逐条确认，每条都能点回简历原文证据。上面是资料完整度检查，每项 5 个检查点，只统计已确认且找得到原文的信息，不评价能力。

（操作：滚到岗位比较区，展示得分拆解）

这是六维画像和岗位适配分，技能缺口逐条列出。

（操作：点开诊断报告）

诊断报告由千问写作、DeepSeek 评审，包含岗位关键词覆盖和投递检查清单。

（操作：演示面试练习一题）

面试练习：千问出题、DeepSeek 评价、千问复盘；回答按规则给分——回应关键词、达到字数、含可核对数字各加一分，封顶 5 分。

（操作：点击导出）

最后导出 HTML 报告，浏览器打印即 PDF。

（操作：地址栏打开 /developer）

面向开发者还有 /developer 工作台：求职、面试、比赛三类精准场景攻略，联网来源可逐条点开。

验证结果：17 个 Dify 工作流真实链路通过、22 项浏览器回归全部通过、五种视口截图无横向溢出。

## 6. 后续计划（约 40 秒）

（操作：停在报告页或首页）

下一步计划：

- **DOCX 原生简历导出**并通过真实 ATS 验证；
- 接入更多检索供应商，建立官方域名白名单；
- 比赛真题库建设，只收录公开来源；
- **六维权重开放自定义配置**，让用户按行业调整；
- 多人协作与设备间同步。

尚待解决的问题：联网检索需要配置 Tavily Key（未配置时诚实标注"未联网核验"）；职业影像功能因供应商额度限制暂时关闭。

一句话收尾：就业罗盘不替用户做决定——它把每一份建议，变成可以核对、可以执行、可以交付的文档。**真实，是最好的简历。**
