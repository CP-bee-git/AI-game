# 需要你提供或确认的配置

这些事项无法由代码仓库自动决定，开发时按优先级补齐即可。

## 现在需要

- 选择一个云端模型供应商：通义千问或 DeepSeek。
- 对应的 API Key，放入本地 `.env`，不要提交到 Git。
- 确认聊天模型名称，例如 `qwen-plus` 或 `deepseek-chat`。
- Embedding 模型和向量维度，用于后续岗位匹配；可以使用供应商的 Embedding API。
- 一份脱敏示例简历和 10-20 份脱敏岗位 JD，用于回归测试。
- OCR worker 的 Python 3.12 运行环境；PaddleOCR 已列入 `backend[ocr]`，图片解析暂时保留占位。

画像、岗位匹配、诊断和文本面试已经可以用 API 联调；当前数据暂存在内存中，服务重启后会清空，下一阶段接入 PostgreSQL 持久化。

## 联调前需要

- 云端 API 的月度额度和单次调用预算。
- 简历文件最大大小和允许的保留时间。
- 第一版是否需要登录，还是先使用演示账号。
- 岗位数据是手工导入，还是已有学校/合作方接口。

## 公网部署前需要

- 云服务器或容器平台账号。
- PostgreSQL/pgvector、Redis 和对象存储（OSS/S3）的生产配置。
- HTTPS 域名和 DNS 管理权限。
- 隐私政策、数据删除规则和管理员账号。
